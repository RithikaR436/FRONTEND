Chapter 03

Primitive Data Types, Stack Memory Allocation & Immutability

A deep architectural investigation into the 7 primitive data types of JavaScript. We explore how primitive values are allocated by value directly onto the Call Stack, understand the mathematical necessity of immutability, and examine the internal autoboxing mechanism powering wrapper objects.

3.1 Exhaustive Architectural Breakdown of All 7 Primitives

1 String (UTF-16 Sequences & Code Points)

Strings represent textual data encoded as a sequence of 16-bit unsigned integer values (UTF-16 code units). JavaScript strings are strictly immutable and indexed starting at index 0. 

const greeting = "Hello, Modern JavaScript!";
console.log(greeting.length);           // 26
console.log(greeting.indexOf("Modern")); // 7
console.log(greeting.substring(0, 5));  // "Hello"

// Attempting in-place mutation (Silently fails or throws in strict mode):
greeting[0] = "W";
console.log(greeting); // "Hello, Modern JavaScript!" (Unchanged!)

2 Number (IEEE 754 Double Precision Floating Point)

JavaScript uses a single format for all numbers: 64-bit IEEE 754 double precision (52 bits for mantissa, 11 bits for exponent, 1 sign bit). The safe integer range is \( -(2^{53} - 1) \) to \( 2^{53} - 1 \) (Number.MAX_SAFE_INTEGER = 9,007,199,254,740,991). 

console.log(0.1 + 0.2);               // 0.30000000000000004
console.log(Math.abs((0.1 + 0.2) - 0.3) < Number.EPSILON); // true
console.log(1 / 0);                   // Infinity
console.log(-1 / 0);                  // -Infinity
console.log(0 / 0);                   // NaN

3 BigInt (Arbitrary Precision Integers)

Introduced in ES2020 to handle high-precision timestamps, large database IDs, and cryptography without numeric truncation. 

const maxSafe = BigInt(Number.MAX_SAFE_INTEGER); // 9007199254740991n
const nextValue = maxSafe + 1n;                  // 9007199254740992n
const nextAgain = maxSafe + 2n;                  // 9007199254740993n

console.log(nextValue !== nextAgain);             // true

4 Boolean (Logical Truth State)

Contains only two literal values: true and false. Used throughout control flow branches and predicates. 

const isAuthenticated = true;
const hasWriteAccess = false;
console.log(isAuthenticated && hasWriteAccess); // false

5 & 6 Undefined vs Null

Undefined: System-assigned default value when an identifier has been allocated in memory but not yet assigned any value.
Null: Programmer-assigned primitive representing the intentional absence of any object reference or value. 
let unassigned;
console.log(unassigned);         // undefined

let emptyUser = null;
console.log(emptyUser);          // null

console.log(null == undefined);  // true  (Loose equality)
console.log(null === undefined); // false (Strict equality)

7 Symbol (Unique Object Identifiers)

Every invocation of Symbol() creates a unique, immutable primitive identifier, even if instantiated with the exact same description string. 

const idKey1 = Symbol("userId");
const idKey2 = Symbol("userId");

console.log(idKey1 === idKey2); // false (Unique tokens)

const account = {
  username: "alex_99",
  [idKey1]: "INTERNAL_UUID_8912"
};

console.log(account[idKey1]);        // "INTERNAL_UUID_8912"
console.log(Object.keys(account));   // ["username"]

3.2 Memory Allocation: The Call Stack & By-Value Copying

Because primitives have a fixed, static size in memory, the engine allocates them directly into the Call Stack execution frame. When you copy a primitive, a brand-new, completely independent copy of that value is written to a new stack slot: 

let originalNumber = 100;
let clonedNumber = originalNumber; // Copies the primitive numeric value 100 directly

clonedNumber = 200; // Modifying clonedNumber

console.log("Original:", originalNumber); // 100 (Completely unaffected!)
console.log("Cloned:", clonedNumber);     // 200

3.3 Autoboxing & Primitive Wrapper Objects Lifecycle

If primitives are not objects and have no methods, how does "text".toUpperCase() or (123.456).toFixed(2) work?

// Engine Autoboxing Lifecycle

1. Engine encounters: "javascript".toUpperCase()

2. Autoboxing: Temporarily constructs object wrapper: new String("javascript")

3. Dispatches method from String.prototype.toUpperCase

4. Returns new primitive string "JAVASCRIPT"

5. Discards temporary object wrapper immediately for garbage collection!

// Proof of temporary wrapper object discard:
const str = "hello";
str.customProp = 999; // Property attached to temporary String wrapper, which is instantly discarded!

console.log(str.customProp); // Output: undefined

3.4 Top 5 Senior Technical Interview Questions & Answers

Q1: Why are primitive values in JavaScript immutable?

Primitives are stored by value in the Stack with fixed memory sizes. Immutability ensures thread-safe deterministic execution, enables V8 memory optimizations like String interning/pooling (reusing the same string memory across multiple variables), and guarantees that passing values into functions cannot cause unexpected side effects.

Q2: What is the difference between Symbol() and Symbol.for()?

Symbol("key") always creates a brand-new, isolated unique symbol in memory. Symbol.for("key") searches the global Symbol registry: if a symbol with that key already exists, it returns that exact symbol reference; otherwise, it registers and returns a new shared symbol across modules and iframes.

Q3: Why does 0.1 + 0.2 !== 0.3 in JavaScript?

Under IEEE 754, fractional decimal numbers like 0.1 and 0.2 convert to infinitely repeating binary fractions. When truncated to 53 bits of mantissa precision, their sum evaluates to 0.30000000000000004.

Q4: What is Autoboxing and how does it affect memory?

Autoboxing is the automatic creation of a temporary object wrapper (new String(), new Number()) when accessing methods on a primitive value. Once the method executes, the wrapper object is immediately eligible for garbage collection, preventing persistent memory bloat.

Q5: How can you check if a number is within the safe integer limits?

Use the standard method Number.isSafeInteger(val), which verifies that the value is an integer between Number.MIN_SAFE_INTEGER and Number.MAX_SAFE_INTEGER. For integers outside this range, migrate to BigInt.
