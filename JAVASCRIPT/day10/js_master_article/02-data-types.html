Chapter 02

JavaScript Data Types, Type System & Type Coercion Deep Dive

JavaScript features a dynamic and weakly typed runtime system. In this chapter, we dissect the 8 canonical data types defined in the ECMAScript specification, investigate the internal typeof implementation quirks, unpack explicit casting mechanisms, and demystify the abstract algorithms powering implicit type coercion.

2.1 The Nature of JavaScript's Type System

JavaScript is both dynamically typed and weakly typed:

1. Dynamically Typed

Types are associated with runtime values, not with variable identifiers. You do not specify variable types at compile time; variables can be reassigned values of completely different types at any point. 

let dynamicRef = 42;          // Currently holds Number
dynamicRef = "Hello V8";      // Now holds String
dynamicRef = { id: 101 };     // Now holds Object

2. Weakly Typed (Implicit Conversion)

When an operation involves mismatched types, the engine does not throw a type error immediately; instead, it automatically performs implicit type coercion behind the scenes. 

const result = "Score: " + 100; // Automatically converts 100 to "100"
console.log(result);           // "Score: 100" (String concatenation)

2.2 Complete Taxonomy of the 8 ECMAScript Data Types

The ECMAScript standard classifies all values into 8 distinct data types, grouped into 7 Primitives and 1 Non-Primitive / Reference Type:

Primitive Types (7 Types)

Stored by Value • Stack Memory • Immutable
1. String UTF-16 textual sequences (e.g. "hello")
2. Number IEEE 754 64-bit float (e.g. 42, 3.14, NaN)
3. BigInt Arbitrary precision integers (e.g. 9007199254740993n)
4. Boolean Logical truth states: true or false
5. Undefined Default state of unassigned identifiers
6. Null Explicit intentional absence of object reference
7. Symbol Unique, collision-free object key identifier (ES6)

Non-Primitive / Reference Type

Stored by Reference • Heap Memory • Mutable
Object (Plain) Key-value dictionaries ({ key: value })
Array Indexed ordered lists ([1, 2, 3])
Function First-class callable executable objects
Date & RegExp Built-in utility standard objects
Map & Set ES6 Keyed hash collections & unique sets
WeakMap & WeakSet Garbage-collectible weak reference collections

2.3 The typeof Operator & Historical Quirks

The unary operator typeof returns a string representing the evaluation type of the operand. However, there are famous historical artifacts in its behavior:

1. The typeof null === "object" Bug

In early JavaScript, values were stored with a 32-bit type tag. Objects had a type tag of 000. Since null was represented as a NULL pointer (all zeros), typeof null mistakenly identified it as an object. This behavior cannot be fixed now without breaking legacy web applications.

2. The typeof NaN === "number" Rule

NaN stands for "Not a Number", but in the IEEE 754 floating-point specification, it is a special numeric value representing an unrepresentable mathematical result (e.g. 0 / 0). Hence, its type is "number". 

// Complete typeof testing suite:
console.log(typeof "Hello");         // "string"
console.log(typeof 100);             // "number"
console.log(typeof 9007199254740991n);// "bigint"
console.log(typeof true);            // "boolean"
console.log(typeof undefined);       // "undefined"
console.log(typeof Symbol("key"));   // "symbol"
console.log(typeof null);            // "object"  ⚠️ (Historical bug)
console.log(typeof {});              // "object"
console.log(typeof [1, 2, 3]);       // "object"  ⚠️ (Arrays are Objects)
console.log(typeof function() {});   // "function"

// The Bulletproof Type Checker (Production Utility):
function getExactType(value) {
  return Object.prototype.toString.call(value).slice(8, -1).toLowerCase();
}

console.log(getExactType(null));        // "null"        ✅ (Correct!)
console.log(getExactType([1, 2, 3]));   // "array"       ✅ (Correct!)
console.log(getExactType(new Date()));  // "date"        ✅ (Correct!)
console.log(getExactType(/abc/g));      // "regexp"      ✅ (Correct!)

2.4 The 8 Falsy Values in JavaScript

When converted to Boolean context (e.g. inside an if condition), only these 8 values evaluate to false. Every other value in JavaScript is Truthy (including empty arrays [] and empty objects {}!):

Falsy Value Type Boolean(val) Explanation
false boolean false The boolean literal false.
0 number false The numeric zero.
-0 number false Negative zero in IEEE 754 floating point.
0n bigint false The BigInt zero literal.
"" string false An empty string literal (length 0).
null null false Absence of any object value.
undefined undefined false Uninitialized variable default state.
NaN number false Not-a-Number arithmetic failure.

2.5 Top 5 Senior Technical Interview Questions & Answers

Q1: What is the output of [] + [] and [] + {}?

[] + [] outputs "" (empty string) because the + operator triggers ToPrimitive, converting empty arrays to "". [] + {} outputs "[object Object]" because "" + "[object Object]" = "[object Object]".

Q2: How do you accurately distinguish between an Array, an Object, and null?

Because typeof returns "object" for all three, we must use: Array.isArray(val) for Arrays, val === null for null, and typeof val === "object" && val !== null && !Array.isArray(val) for plain objects. Alternatively, use Object.prototype.toString.call(val).

Q3: What is the difference between explicit casting and implicit coercion?

Explicit casting occurs when the developer deliberately invokes conversion constructors like Number("42"), String(100), or Boolean(0). Implicit coercion occurs automatically behind the scenes during operations like "5" * 2 (evaluates to 10) or if ("hello") (evaluates to true).

Q4: Why does NaN === NaN evaluate to false?

Under IEEE 754 specification rules, NaN represents an unspecifiable calculation error. Two distinct calculation failures (e.g. 0 / 0 vs Math.sqrt(-1)) cannot be considered equal to one another. To safely test for NaN, use Number.isNaN(val) or Object.is(val, NaN).

Q5: What is the BigInt type and why can it not be mixed with Numbers?

BigInt represents arbitrarily large integers beyond Number.MAX_SAFE_INTEGER (\( 2^{53}-1 \)). JavaScript strictly prevents implicit arithmetic mixing between BigInt and Number (throwing a TypeError) to prevent silent precision degradation bugs.
