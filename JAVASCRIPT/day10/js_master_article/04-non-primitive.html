Chapter 04

Non-Primitive (Reference) Types, Heap Memory & Deep Cloning

Non-primitive types (Objects, Arrays, Functions, Map, Set) represent dynamic, mutable data structures. In this chapter, we explore how the V8 engine allocates objects dynamically in the Memory Heap, demystify the Pass-by-Reference pointer mechanics, and compare production cloning algorithms.

4.1 The Non-Primitive Family in ECMAScript

1. Plain Objects

Unordered collections of key-value pairs where keys are strings or symbols. 

const user = {
  id: 101,
  name: "Priya",
  role: "Full Stack Engineer"
};

2. Arrays

High-level, list-like ordered objects inheriting from Array.prototype. 

const techStack = ["React", "Node", "Postgres"];
techStack.push("Docker");
console.log(techStack.length); // 4

3. Functions

First-class objects that can be stored in variables, passed, and returned. 

function calculateTax(amount) {
  return amount * 0.18;
}
console.log(calculateTax(5000)); // 900

4.2 Stack Pointer vs Heap Memory Architecture

Because objects, arrays, and functions can grow dynamically to arbitrary sizes, they cannot be stored directly on the contiguous Call Stack. Instead, JavaScript allocates the object payload inside the Memory Heap, while storing only the fixed-size Memory Reference Address Pointer on the Call Stack:

CALL STACK (Fast, Sequential)
let id = 101 Value: 101
let profile Pointer: @0x7FFF92
MEMORY HEAP (Dynamic Pool)
Heap Memory Address: @0x7FFF92
{ name: "Priya", role: "Dev", active: true }

4.3 Pass-by-Reference (Copying the Pointer)

When you assign an existing object to a new variable, JavaScript copies the memory address pointer, NOT the object data. Both variables now point to the exact same object in the Heap: 

const userAccountA = { username: "vignesh", credits: 50 };
const userAccountB = userAccountA; // Copies pointer address @0x..., NOT the object!

// Mutating via userAccountB:
userAccountB.credits = 100;

console.log("Account A credits:", userAccountA.credits); // Output: 100 ⚠️ (Mutated!)
console.log("Are pointers identical?", userAccountA === userAccountB); // true

4.4 Shallow Copy vs Deep Copy Techniques

1. Shallow Copy (1-Level Deep)

Copies top-level properties by value, but nested objects still share memory references! 

const source = {
  title: "Book",
  author: { name: "Robert" }
};

// Method 1: Spread Operator {...}
const shallow1 = { ...source };

// Method 2: Object.assign()
const shallow2 = Object.assign({}, source);

shallow1.author.name = "Martin";
console.log(source.author.name); // "Martin" ⚠️ (Nested mutation leaked!)

2. Deep Copy (Complete Clone)

Recursively clones all levels, completely severing all memory connections. 

const source = {
  title: "Book",
  author: { name: "Robert" }
};

// Modern Standard: structuredClone()
const deepClone = structuredClone(source);

deepClone.author.name = "Uncle Bob";
console.log(source.author.name); // "Robert" ✅ (Completely safe!)

// Legacy Fallback: JSON Serialization
const jsonClone = JSON.parse(JSON.stringify(source));

4.5 Top 5 Senior Technical Interview Questions & Answers

Q1: What are the limitations of JSON.parse(JSON.stringify(obj)) for cloning?

JSON cloning fails in multiple scenarios: it ignores functions, removes properties with undefined or Symbol values, converts Date objects to strings, converts NaN and Infinity to null, and throws a TypeError on circular references. In modern JavaScript, use structuredClone() instead.

Q2: Is JavaScript "Pass by Value" or "Pass by Reference"?

JavaScript is strictly Pass by Value (often termed "Pass by Sharing" for objects). When passing an object into a function, the value being copied and passed into the parameter is the memory reference pointer. Mutating properties modifies the underlying heap object, but reassigning the parameter identifier creates a new local pointer without altering the external variable.

Q3: What is the difference between Map and a plain JavaScript Object?

In plain Objects, keys must be Strings or Symbols; in Map, any data type (including objects, functions, and numbers) can be a key. Map preserves insertion order, provides an accurate .size property, and offers optimized performance for frequent key additions and removals.

Q4: What is WeakMap and when should you use it?

A WeakMap is a collection where keys must be objects and are held weakly. If there are no other references to a key object elsewhere in code, the garbage collector will automatically collect the object and remove its entry from the WeakMap. It is ideal for storing private object metadata and avoiding memory leaks with DOM elements.

Q5: How does JavaScript Garbage Collection clean up Heap memory?

Modern engines use the Mark-and-Sweep Algorithm. Starting from "roots" (Global object, active call stack frames), the engine marks all reachable objects in the Heap. Any object that is unreachable (no reference paths leading from roots) is swept and its memory reclaimed.
