Chapter 07

JavaScript Hoisting & Execution Context Internals

Hoisting is the default behavior of the JavaScript engine wherein variable, function, and class declarations are allocated into memory during the Creation Phase before any single line of code is actually executed.

💡 சுருக்கம் (Summary in Tamil): Hoisting என்றால் கோட் மேலே நகர்த்தப்படுகிறது என்று அர்த்தமல்ல! JavaScript இன்ஜின் கோடை இயக்குவதற்கு முன் (Memory Creation Phase-ல்), அனைத்து declarations-களுக்கும் மெமரியை ஒதுக்குகிறது. var மெமரியில் undefined என சேமிக்கப்படும்; Function Declarations முழுமையாக சேமிக்கப்படும்; ஆனால் let மற்றும் const TDZ (Temporal Dead Zone)-ல் வைக்கப்படும்!

7.1 Execution Context: Phase 1 vs Phase 2

Whenever JavaScript executes code, it creates an Execution Context consisting of two distinct runtime phases:

Phase 1: Memory Creation Phase
  • Engine scans through the entire script.
  • Allocates memory slots for all identifiers.
  • var is initialized with undefined.
  • function declarations are stored with their full implementation.
  • let / const are allocated in an uninitialized (TDZ) state.
Phase 2: Code Execution Phase
  • Engine executes code line-by-line from top to bottom.
  • Assigns real evaluated values to variables.
  • Invokes functions and evaluates mathematical/logical expressions.
  • Pushes new function execution contexts onto the Call Stack.

7.2 Function Declarations vs Function Expressions

One of the biggest interview traps is distinguishing between Function Declarations and Function Expressions/Arrow Functions: 

// 1. Function Declaration (Fully Hoisted!)
sayHello(); // ✅ Output: "Hello from declaration!" (Works perfectly!)

function sayHello() {
  console.log("Hello from declaration!");
}

// 2. Function Expression with var
try {
  sayGoodbye(); // ❌ TypeError: sayGoodbye is not a function (It is currently undefined!)
} catch (e) {
  console.error(e.message);
}

var sayGoodbye = function() {
  console.log("Goodbye!");
};

// 3. Arrow Function with let/const
try {
  greetArrow(); // ❌ ReferenceError: Cannot access 'greetArrow' before initialization (TDZ)
} catch (e) {
  console.error(e.message);
}

const greetArrow = () => console.log("Hello Arrow!");

7.3 Classic Hoisting Interview Puzzles

Puzzle #1: Function vs Variable with Same Name

What gets logged in the console below?

var myData = 10;

function myData() {
  console.log("I am a function");
}

console.log(typeof myData); // Output: "number"
// Explanation: In Phase 1, the function declaration hoists first. In Phase 2, myData = 10 overwrites the reference with number 10!

Puzzle #2: Shadowed Var in Local Function

var city = "Chennai";

function printCity() {
  console.log("City inside:", city); // Output: undefined ⚠️ (Not "Chennai"!)
  var city = "Bangalore";
  console.log("City updated:", city); // Output: "Bangalore"
}

printCity();
// Explanation: Inside printCity, local 'var city' is hoisted to the top of the function scope as undefined, shadowing the global "Chennai"!
