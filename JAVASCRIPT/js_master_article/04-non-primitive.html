Chapter 04

Non-Primitive (Reference) Types, Heap Memory & Cloning

Non-primitive types (also known as Reference Types) include Objects, Arrays, Functions, Maps, Sets, and Dates. They do not store their data directly in the call stack; instead, they are allocated in the Memory Heap and accessed via memory reference addresses.

💡 சுருக்கம் (Summary in Tamil): Non-Primitive வகைகள் (Objects, Arrays, Functions போன்றவை) அளவிட முடியாத பெரிய தரவுகளைக் கொண்டிருக்கும் என்பதால், அவை Heap Memory-ல் வைக்கப்படுகின்றன. Call Stack-ல் அவற்றின் Memory Address (Reference pointer) மட்டுமே இருக்கும். எனவே ஒரு ஆப்ஜெக்ட்டை இன்னொரு வேரியபிளுக்கு அசைன் செய்யும் போது, Reference மட்டுமே காப்பியாகும் (Pass by Reference)!

4.1 The Core Non-Primitive Structures

Plain Objects

Key-value dictionaries supporting string and symbol keys.

const user = {
  id: 101,
  name: "Priya",
  active: true
};

Arrays

Ordered, indexed collections inheriting from Array.prototype.

const skills = ["JS", "React", "Node"];
skills.push("TypeScript");
console.log(skills[0]); // "JS"

Functions

First-class objects that can be passed as arguments and returned.

function calculateTax(subtotal) {
  return subtotal * 0.18;
}
console.log(calculateTax(1000)); // 180

4.2 Stack vs Heap Memory Architecture

When you declare a primitive, its value is placed right on the Call Stack. When you declare an object, the object is placed in the Heap, and only the reference address pointer is placed on the Stack:

CALL STACK (Fast, Static Size)
let age = 30 Value: 30
let person Pointer: @0x10A4B
MEMORY HEAP (Dynamic, Flexible)
Heap Address: @0x10A4B { name: "Divya", city: "Madurai" }

4.3 Pass-by-Reference Demonstration

Assigning an object to another variable does not duplicate the data. It copies the reference pointer! 

// Notice how modifying obj2 mutates obj1!
const obj1 = { name: "Anand", score: 90 };
const obj2 = obj1; // Copies pointer address @0x..., NOT the object!

obj2.score = 100;

console.log("obj1 score:", obj1.score); // 100 ⚠️ (Both variables point to the same heap object)
console.log("Are they equal?", obj1 === obj2); // true (Identical reference)

4.4 Shallow Copy vs Deep Copy Techniques

1. Shallow Copy (1-Level Deep)

Copies top-level properties by value, but nested objects still share memory references!

const original = {
  name: "Karan",
  address: { city: "Salem" }
};

// Method A: Spread Operator {...}
const shallowCopy = { ...original };

// Method B: Object.assign
const shallowCopy2 = Object.assign({}, original);

shallowCopy.address.city = "Coimbatore";
console.log(original.address.city); // "Coimbatore" ⚠️ Nested object mutated!

2. Deep Copy (Independent Clone)

Recursively clones all levels, completely severing all memory connections.

const original = {
  name: "Karan",
  address: { city: "Salem" }
};

// Modern Standard: structuredClone()
const deepCopy = structuredClone(original);

deepCopy.address.city = "Tiruchirappalli";
console.log(original.address.city); // "Salem" ✅ (Completely safe!)

// Legacy Fallback: JSON serialization
const legacyDeep = JSON.parse(JSON.stringify(original));

4.5 ES6 Keyed Collections: Map & Set

ES6 introduced Map and Set for efficient key-value pairs with arbitrary key types (including Objects as keys!) and unique value collections: 

// 1. Map allows any data type as key:
const configMap = new Map();
const keyObj = { role: "admin" };

configMap.set(keyObj, "Full permissions");
console.log(configMap.get(keyObj)); // "Full permissions"
console.log(configMap.size);        // 1

// 2. Set guarantees unique entries (deduplication):
const duplicates = [1, 2, 2, 3, 4, 4, 5];
const unique = [...new Set(duplicates)];
console.log("Deduplicated Array:", unique); // [1, 2, 3, 4, 5]
