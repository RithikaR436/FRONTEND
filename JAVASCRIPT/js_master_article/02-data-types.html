Chapter 02

JavaScript Data Types & Type System Deep Dive

JavaScript is a dynamically typed and loosely typed language. Data types tell the runtime engine what kind of operations can be performed on a value and how much memory to allocate.

💡 சுருக்கம் (Summary in Tamil): JavaScript-ல் மொத்தம் 8 Data Types உள்ளன. அவை இரண்டு முக்கிய வகைகளாகப் பிரிக்கப்படுகின்றன: 7 Primitive Types (மதிப்பு மாறாதவை, Stack memory-ல் சேமிக்கப்படுபவை) மற்றும் 1 Non-Primitive / Reference Type (Object - Heap memory-ல் சேமிக்கப்படுபவை).

2.1 Dynamic Typing vs Static Typing

In JavaScript, variable declarations are not bound to a specific data type. Instead, types belong to values, not variables. A variable can hold any value and change its type at runtime. 

// Dynamic typing in action
let dynamicVal = 100;          // Number type
console.log(typeof dynamicVal); // "number"

dynamicVal = "Hello World";    // Reassigned to String type
console.log(typeof dynamicVal); // "string"

dynamicVal = { id: 1 };        // Reassigned to Object type
console.log(typeof dynamicVal); // "object"

2.2 The Complete Taxonomy of 8 JavaScript Types

1. Primitive Data Types (7 Types)

Stored by Value • Stack Memory • Immutable
  • string Textual data (e.g. "hello")
  • number IEEE 754 float (e.g. 42, 3.14, NaN)
  • bigint Arbitrary precision integers (e.g. 9007199254740993n)
  • boolean Logical entities: true or false
  • undefined Variable declared but not assigned
  • null Intentional absence of any object value
  • symbol Unique and immutable primitive identifier (ES6)

2. Non-Primitive / Reference (1 Core Type)

Stored by Reference • Heap Memory • Mutable
  • Object Key-value collections ({ name: "John" })
  • Array Indexed collections (sub-type of Object)
  • Function Callable code blocks (first-class objects)
  • Date / RegExp Built-in utility standard objects
  • Map / Set Keyed hash maps & unique sets (ES6)

2.3 The typeof Operator & Tricky Quirks

The typeof operator returns a string representing the evaluation type of the operand. However, there are famous historical design quirks you must know for interviews:

⚠️ The Null Bug: typeof null === "object"
In the first implementation of JavaScript (1995), values were represented as type tags. The tag for objects was 0, and null was represented as NULL pointer (0x00), causing typeof null to return "object".
ℹ️ NaN (Not a Number): typeof NaN === "number"
NaN represents an unrepresentable or erroneous numeric calculation result, but its specification data type remains numeric. 
// Testing typeof on all categories:
console.log(typeof "Hello");         // "string"
console.log(typeof 123);             // "number"
console.log(typeof 9007199254740991n);// "bigint"
console.log(typeof true);            // "boolean"
console.log(typeof undefined);       // "undefined"
console.log(typeof Symbol("id"));    // "symbol"
console.log(typeof null);            // "object"  ⚠️ (Historical bug)
console.log(typeof {});              // "object"
console.log(typeof [1, 2, 3]);       // "object"  ⚠️ (Arrays are Objects)
console.log(typeof function() {});   // "function" (Special object return)

2.4 Type Coercion: Implicit vs Explicit

Type Coercion is the automatic or manual conversion of values from one data type to another (e.g. string to number, object to boolean).

Explicit Coercion (Type Casting)

When the developer intentionally converts types using built-in constructors:

const strNum = "42";
const parsed = Number(strNum);  // 42 (number)
const boolVal = Boolean(1);    // true
const text = String(100);      // "100"

Implicit Coercion (Automatic Conversion)

When JavaScript automatically converts types during operators or comparisons:

console.log("5" + 2);   // "52" (String concatenation!)
console.log("5" - 2);   // 3    (Numeric subtraction!)
console.log("5" * "2"); // 10   (Numeric multiplication)
console.log(!0);        // true (Boolean conversion)
