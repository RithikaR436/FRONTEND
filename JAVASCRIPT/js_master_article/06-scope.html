Chapter 06

JavaScript Scope, Lexical Environment & Closures Masterclass

Scope defines the current context of execution in which values and expressions are visible and accessible. Closures are one of JavaScript's most powerful architectural features, allowing inner functions to retain access to their outer lexical environment even after the parent function has finished executing.

6.1 The 4 Scope Levels in JavaScript

1. Global Scope

Variables declared outside any function or block. Accessible anywhere in the application.

const appName = "MasterJS";
function showApp() {
  console.log(appName); // Accessible!
}

2. Function / Local Scope

Variables declared inside a function body. Accessible only within that function.

function processPayment() {
  const secretKey = "sk_test_9912";
  console.log(secretKey); // Accessible inside
}
// console.log(secretKey); // ❌ ReferenceError

3. Block Scope (let & const)

Variables enclosed within curly braces { ... } (such as if, for, while).

{
  let blockVariable = "Scoped inside block";
}
// console.log(blockVariable); // ❌ ReferenceError

4. Module Scope

In ES Modules (ESM), variables are scoped to the file unless explicitly exported.

// In math.js:
const internalHelper = () => {};
export const add = (a, b) => a + b;

6.2 Lexical Scoping & The Scope Chain Resolution

Lexical Scope means that variable resolution is determined statically by the physical location of the code in the source file. When a variable is requested, the engine searches:

Step 1: Current Local Scope (Check current function / block environment)
↑ (If not found, climb up)
Step 2: Outer Lexical Environment (Parent function scope)
↑ (If not found, climb up)
Step 3: Global Scope (Window / globalThis)
↑ (If not found in Global)
❌ Throws ReferenceError: variable is not defined 
const globalGreeting = "Hello";

function outer() {
  const outerName = "Vikram";

  function inner() {
    const innerRole = "Developer";
    // Climbs scope chain to resolve globalGreeting and outerName:
    console.log(`${globalGreeting}, ${outerName} is a ${innerRole}`);
  }

  inner();
}
outer(); // "Hello, Vikram is a Developer"

6.3 Variable Shadowing & Illegal Shadowing

Variable Shadowing occurs when an inner scope declares a variable with the exact same name as an outer scope variable, overriding/shadowing it within that block. 

let color = "Blue"; // Outer variable

function paint() {
  let color = "Red"; // Shadows outer 'color' inside paint()
  console.log("Inside function:", color); // "Red"
}

paint();
console.log("Outside function:", color); // "Blue" (Original intact)

// Illegal Shadowing Rule:
// You CANNOT shadow a 'let' with a 'var' inside a block!
let score = 50;
{
  // var score = 100; // ❌ SyntaxError: Identifier 'score' has already been declared
}

6.4 Closures Deep Dive & Real-World Use Cases

A closure is formed when a function retains a reference to variables in its enclosing lexical environment, even when that function is invoked outside its original scope.

1. Data Privacy / Encapsulation (Private Counters)

The internal count variable cannot be modified directly from outside; it can only be changed via exposed methods. 

function createCounter(initialValue = 0) {
  let count = initialValue; // Private variable (closed over)

  return {
    increment: () => ++count,
    decrement: () => --count,
    getCount: () => count
  };
}

const counterA = createCounter(10);
console.log(counterA.increment()); // 11
console.log(counterA.increment()); // 12
console.log(counterA.getCount());  // 12
console.log(counterA.count);      // undefined (Private variable protected!)

2. Famous Interview Bug: var vs let in setTimeout Loop

With var, a single shared binding exists. With let, each iteration creates a new fresh block-scoped binding for the closure! 

// Problematic with var (Prints: 3, 3, 3):
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log("var loop:", i), 100);
}

// Fixed with ES6 let (Prints: 0, 1, 2):
for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log("let loop:", j), 100);
}
