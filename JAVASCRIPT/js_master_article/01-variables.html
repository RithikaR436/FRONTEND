Chapter 01

JavaScript Variables: var, let, const & The Temporal Dead Zone

A variable in JavaScript is a named container used to store data in memory. Understanding how JavaScript allocates memory, manages scope, and initializes variables is fundamental to writing bug-free, modern applications.

💡 சுருக்கம் (Summary in Tamil): வேரியபிள் என்பது மெமரியில் தகவல்களை (Data) சேமிக்கப் பயன்படும் ஒரு பெயர் கொண்ட கொள்கலன் (Container). JavaScript-ல் var, let, மற்றும் const என மூன்று வழிகளில் வேரியபிள்களை உருவாக்கலாம். இவற்றின் Scope, Re-assignment மற்றும் Hoisting நடத்தை முற்றிலும் மாறுபட்டவை!

1.1 Variable Lifecycle & Key Terminology

When the JavaScript engine processes a variable, it undergoes three distinct lifecycle phases:

Phase 1

Declaration

The variable identifier is registered in its enclosing scope/environment record.

Phase 2

Initialization

Memory is allocated and the variable is initialized with a default value (e.g. undefined).

Phase 3

Assignment

The actual developer-specified value is stored in the allocated memory slot.

// Example: Lifecycle demonstration
let userAge;          // Declaration + Initialization (implicitly undefined)
console.log(userAge); // undefined

userAge = 25;         // Assignment phase
console.log(userAge); // 25

1.2 Comprehensive Comparison: var vs let vs const

Before ES6 (2015), var was the only keyword to declare variables. ES6 introduced let and const to solve scoping issues, accidental overwrites, and memory leakage.

Feature var (Legacy ES5) let (Modern ES6) const (Modern ES6)
Scope Level Function Scope or Global Scope Block Scope { ... } Block Scope { ... }
Re-declaration Allowed in same scope ❌ SyntaxError ❌ SyntaxError
Re-assignment Allowed (Mutable) Allowed (Mutable) ❌ TypeError (Immutable binding)
Must Initialize on Declaration? No (Defaults to undefined) No (Defaults to undefined) Yes (SyntaxError if omitted)
Hoisting Behavior Hoisted & initialized as undefined Hoisted, but in TDZ (ReferenceError) Hoisted, but in TDZ (ReferenceError)
Attaches to Window / Global Object? Yes (window.x) No No

1.3 Code Examples & Behavioral Deep Dive

1. The Pitfalls of var (Scope Leakage)

var ignores block statements such as if blocks, for loops, and while loops. 

// Notice how 'count' leaks outside the if block!
if (true) {
  var count = 10;
}
console.log("Outside if block with var:", count); // Prints: 10 (Leaked!)

// But with let or const:
if (true) {
  let secureCount = 20;
}
// console.log(secureCount); // ❌ Uncaught ReferenceError: secureCount is not defined

2. const with Objects & Arrays (Binding vs Mutability)

Important Rule: const creates an immutable variable identifier binding, NOT an immutable value! You cannot re-assign the variable, but you can mutate internal object/array properties. 
const developer = {
  name: "Arun",
  role: "Frontend Engineer"
};

// Valid: Mutating properties
developer.role = "Full Stack Architect";
developer.city = "Chennai";
console.log("Updated object:", developer);

// Invalid: Reassigning the binding throws an Error
try {
  developer = { name: "Vijay" }; // ❌ TypeError: Assignment to constant variable.
} catch (e) {
  console.error(e.message);
}

// Freezing an object completely:
const immutableUser = Object.freeze({ username: "john_doe" });
// immutableUser.username = "jane"; // Silently fails or throws TypeError in strict mode

1.4 The Temporal Dead Zone (TDZ) Explained

The Temporal Dead Zone (TDZ) is the specific time window between the entering of a scope and the point where a let or const variable is declared and initialized in code.

// Visual Representation of TDZ Timeline
─── Scope Starts Here ───
⏳ TEMPORAL DEAD ZONE (TDZ) ACTIVE
Any access to variable throws ReferenceError: Cannot access 'x' before initialization
─── Declaration Line: let x = 42; ───
✅ TDZ ENDS: Variable 'x' is now safely accessible in memory! 
// Demonstrating the TDZ in action:
function testTDZ() {
  // console.log(heroName); // ❌ ReferenceError: Cannot access 'heroName' before initialization (Inside TDZ)
  
  let heroName = "Spider-Man"; // TDZ ends here
  console.log("After initialization:", heroName); // ✅ Spider-Man
}
testTDZ();

1.5 Modern Industry Best Practices

Rule 1: Default to const

90% of your variables in modern JS should be declared with const. This guarantees variable bindings are not accidentally reassigned.

Rule 2: Use let only when re-assignment is explicitly required

Use let for accumulators, mathematical counters, and loop iterators (e.g. for (let i = 0; i < len; i++)).

Rule 3: Avoid var in modern codebases

var leads to unpredictable hoisting bugs and pollutes the global object.
